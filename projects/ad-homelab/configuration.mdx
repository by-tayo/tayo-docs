Everything here is done via PowerShell and a CSV rather than manually clicking through Active Directory Users and Computers — closer to how bulk provisioning is actually done in real environments, and a stronger demonstration of scripting ability than a GUI walkthrough.

## Getting Files Onto DC01

Scripts land on the host machine first, then get copied onto DC01 through the VMware shared folder set up in the previous phase:

```powershell
New-Item -Path C:\Lab -ItemType Directory -Force
Copy-Item "\\vmware-host\Shared Folders\LabFiles\*.ps1" -Destination C:\Lab
Copy-Item "\\vmware-host\Shared Folders\LabFiles\*.csv" -Destination C:\Lab -ErrorAction SilentlyContinue
cd C:\Lab
Set-ExecutionPolicy RemoteSigned -Scope Process -Force
Get-ChildItem *.ps1 | Unblock-File
```

`Set-ExecutionPolicy RemoteSigned -Scope Process` allows locally-created scripts to run for just this PowerShell session, without weakening the policy machine-wide. `Unblock-File` clears the "downloaded from the internet" flag Windows sometimes attaches to files that arrived via a network path.

## Building the OU Tree and Groups

`setup-ou-structure.ps1` creates the whole department structure in one run: a top-level `Corp` OU, eight department OUs (`IT`, `Finance`, `Sales`, `HR`, `Marketing`, `Engineering`, `Operations`, `Support`) each with `Users` / `Groups` / `Computers` sub-OUs, a `<Department>-Staff` security group per department, and a top-level `Helpdesk` group.

```powershell
Import-Module ActiveDirectory

$domainDN = (Get-ADDomain).DistinguishedName
$topOU    = "Corp"
$departments = @("IT", "Finance", "Sales", "HR", "Marketing", "Engineering", "Operations", "Support")

New-ADOrganizationalUnit -Name $topOU -Path $domainDN -ProtectedFromAccidentalDeletion $true -ErrorAction SilentlyContinue
$topOUPath = "OU=$topOU,$domainDN"

foreach ($dept in $departments) {
    New-ADOrganizationalUnit -Name $dept -Path $topOUPath -ProtectedFromAccidentalDeletion $true -ErrorAction SilentlyContinue
    $deptPath = "OU=$dept,$topOUPath"
    foreach ($sub in @("Users", "Groups", "Computers")) {
        New-ADOrganizationalUnit -Name $sub -Path $deptPath -ProtectedFromAccidentalDeletion $true -ErrorAction SilentlyContinue
    }
    New-ADGroup -Name "$dept-Staff" -GroupScope Global -GroupCategory Security -Path "OU=Groups,$deptPath" -ErrorAction SilentlyContinue
}

New-ADGroup -Name "Helpdesk" -GroupScope Global -GroupCategory Security -Path $topOUPath -ErrorAction SilentlyContinue
```

Run with `.\setup-ou-structure.ps1` — it's idempotent, so re-running it after adding a department to the list only creates what's missing.

## Generating 1,050 Users Without a Large File Transfer

Rather than transferring a large pre-built CSV (which hit the same corruption issue as the scripts — see the warning on the [Build](/projects/ad-homelab/build) page), the user list is **generated directly on DC01** by a short script. It combines a first-name and last-name pool with the eight departments, dedupes `SamAccountName` collisions, and writes straight to `C:\Lab\users_1000.csv`:

```powershell
$firstNames = @("James","Mary","John", "..." )   # ~76 common first names
$lastNames  = @("Smith","Johnson","Williams", "..." )  # ~50 common surnames
$departments = @("IT","Finance","Sales","HR","Marketing","Engineering","Operations","Support")

$rows = @()
$usedSam = @{}
$rand = New-Object System.Random(42)

while ($rows.Count -lt 1050) {
    $fn = $firstNames[$rand.Next(0, $firstNames.Count)]
    $ln = $lastNames[$rand.Next(0, $lastNames.Count)]
    $dept = $departments[$rand.Next(0, $departments.Count)]
    $samBase = ($fn.Substring(0,1) + $ln).ToLower()
    $sam = $samBase; $n = 1
    while ($usedSam.ContainsKey($sam)) { $n++; $sam = "$samBase$n" }
    $usedSam[$sam] = $true
    $rows += [PSCustomObject]@{ FirstName=$fn; LastName=$ln; SamAccountName=$sam; Department=$dept; Password="P@ssw0rd123!" }
}

$rows | Export-Csv -Path C:\Lab\users_1000.csv -NoTypeInformation
```

```powershell
.\generate-users.ps1
```

## Importing Users

`import-users.ps1` reads the CSV, creates each account in the right department's `Users` OU, and adds it to that department's `-Staff` group. It looks up existing users and valid OUs **once** up front rather than per-row (important at 1,000\+ rows), reports progress every 50 users, and skips anyone who already exists — safe to re-run after editing the CSV.

```powershell
.\import-users.ps1
```

```text
Done.
  Created:            1050
  Skipped (existing): 0
  Skipped (no OU):    0
```

<Warning>
  The first version of this script used backtick (\`\`\`) line-continuations inside the `New-ADUser` call. That syntax is fragile against copy/network-share round-trips — trailing whitespace after a backtick silently breaks the continuation and produces confusing parse errors several lines later ("missing closing paren", "unexpected token"). The fix was rewriting the parameter list as a hashtable and splatting it (`New-ADUser @userParams`), which has no line-continuation characters to corrupt.
</Warning>

## Delegating Help-Desk Access

Rather than leaving every administrative task tied to Domain Admin, the `Helpdesk` group gets a single narrow permission — resetting passwords — delegated on the `IT` OU:

1. In **Active Directory Users and Computers**, right-click the `IT` OU → **Delegate Control...**
2. Add the `Helpdesk` group.
3. Grant only **"Reset user passwords and force password change at next logon."**

This is the least-privilege demonstration: a member of `Helpdesk` can reset passwords in `IT` and nothing else — no user creation, no GPO edits, no other OUs — which is the actual point of delegation over handing out broader admin rights.
