This lab builds a working Active Directory environment from scratch: a Windows Server 2022 domain controller, a Windows 11 client joined to the domain, and an isolated internal network that still reaches the internet through the DC. The goal is a corporate network simulation — a realistic base to layer security practices onto later, rather than a one-off exercise in clicking through a role installation wizard.

The part worth paying attention to is the networking. The client sits on a private, isolated network with no direct route out. Everything it does — DHCP lease, DNS resolution, internet access — depends on the domain controller being configured correctly as gateway, DHCP server, and NAT router. Get one of those wrong and the client silently fails in a way that looks like an AD problem but isn't.

## What Gets Built

```text
DC (Server 2022) ─┬─ NAT adapter ────────→ Internet
                  └─ Internal adapter ───→ Isolated LAN ──→ Windows 11 client

Roles on the DC: AD DS · DNS · DHCP · RAS with NAT
```

The domain controller runs four things that matter: Active Directory Domain Services for the domain itself, DNS as a dependency of AD DS, DHCP so the client can lease an address without manual configuration, and Remote Access Server with NAT so traffic from the isolated network can reach the internet through the DC's second adapter.

## Skills Exercised

- Active Directory Domain Services installation and domain creation
- Windows Server role management (DNS, DHCP, Remote Access)
- NAT configuration and routing between isolated and external networks
- DHCP scope and scope option configuration
- PowerShell scripting and execution policy handling
- Bulk user account provisioning at scale
- Domain join and client-side network troubleshooting
