This lab is built to do double duty: a realistic Active Directory environment for practicing day-to-day sysadmin work — domain setup, OU design, bulk provisioning, delegation, GPOs — and a self-contained range for practicing offensive AD techniques and the detection side of the same attacks. It's sized to run comfortably alongside a security toolkit on a single 32GB host, using a hypervisor that's now free for personal use.

## What's Built So Far

```text
Host (32GB RAM, VMware Workstation Pro)
 ├─ VMnet1 (host-only, 192.168.125.0/24)
 │    ├─ pfSense CE — LAN 192.168.125.254 (router, DHCP, firewall for the lab network)
 │    ├─ DC01 — Windows Server 2022 Datacenter, static 192.168.125.10 (Sysmon + Splunk UF)
 │    ├─ CLIENT01 — Windows 11, static 192.168.125.20, joined to corp.lab (Sysmon + Splunk UF)
 │    ├─ LOGSRV — Ubuntu Server 26.04 LTS, static 192.168.125.30, Splunk Enterprise on :9997
 │    └─ Kali attacker VM (existing box, being wired onto VMnet1)
 └─ VMnet8 (NAT — VMware-managed)
      └─ pfSense's WAN interface only — internet access for the whole lab network

DC01 roles: AD DS + DNS
Domain: corp.lab (new forest)
```

pfSense CE now owns routing, DHCP, and firewalling for the entire lab network — replacing an earlier design where every VM carried its own NAT adapter alongside a static IP on the isolated network. That per-VM setup worked at first but proved fragile (a static IP silently reverting to DHCP was the final straw), so the lab now routes through a single dedicated router VM instead, the same way a real network would. See [Architecture](/projects/ad-homelab/architecture) for the full reasoning.

## Skills Exercised

- Active Directory Domain Services installation and forest/domain creation
- VMware Workstation networking — host-only isolation, static addressing, virtual network editor configuration
- Standing up and configuring a dedicated router/firewall (pfSense CE) — interface assignment, DHCP scoping, and re-pointing existing VMs at a new gateway
- Windows 11 client provisioning, including a local-account-only setup (no Microsoft account) to keep the machine clean for later forensics work
- Domain join troubleshooting: diagnosing a static IP silently reverting to DHCP/APIPA, clearing a stale IP binding, and telling networking failures apart from AD failures
- OU design and department-based security group structure, built via PowerShell rather than clicking through ADUC
- Bulk user provisioning at scale (1,050 accounts) from a CSV, including idempotent re-runs and progress reporting
- Real deployment troubleshooting: PowerShell execution policy, file corruption across a network share, and rewriting scripts to avoid fragile syntax (backtick line-continuations) under real-world copy conditions
- Least-privilege delegation of administrative control
- Splunk / SIEM administration — installing Splunk Enterprise on Ubuntu, enabling the forwarder receiver on port `9997`, and running SPL searches (`stats count by host`, filtering by `sourcetype`) to validate the pipeline end to end
- Sysmon deployment on Windows endpoints using the SwiftOnSecurity ruleset, plus a custom `inputs.conf` stanza on the Splunk Universal Forwarder to ship the Sysmon Operational channel alongside the default Windows logs
- Linux storage troubleshooting — diagnosing a silent Splunk index/search failure caused by a full LVM root volume and extending it live with `lvextend` \+ `resize2fs`
- Group Policy authoring and troubleshooting — interactive logon banner, UNC-based desktop wallpaper, and Control Panel / PC Settings restrictions, including using Loopback Processing (Merge mode) to apply User Configuration settings against a Computers OU and verifying with `gpupdate /force` \+ `gpresult /r`
