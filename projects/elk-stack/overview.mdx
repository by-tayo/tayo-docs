This project builds a centralized logging and monitoring stack for a demo application, running entirely in Docker on localhost. Logs are shipped with Filebeat, transported through Kafka, processed by Logstash, indexed into Elasticsearch, and explored in Kibana — with Nagios Core watching the infrastructure underneath.

The design choice worth noting is Kafka. A simpler stack would have Filebeat write straight to Logstash, and for a demo application that would work. Putting an event bus in the middle decouples the shippers from the processors, so producers keep running when Logstash restarts and the pipeline can scale horizontally on either side — which is why real deployments look like this.

## Objectives

- Collect application logs from a Dockerized app in a consistent, structured format
- Use Kafka as a reliable transport layer between log shippers and log processors
- Parse, enrich, and index logs into Elasticsearch for fast querying
- Build Kibana searches and visualizations to analyze `INFO`, `WARNING`, and `ERROR` events
- Use Nagios to monitor service availability across the same environment

## Pipeline

```text
app/app.py → logs/app.log → Filebeat → Kafka (app-logs) → Logstash → Elasticsearch → Kibana
                                                                            ▲
                                                              Nagios (HTTP health checks)
```

## Skills Exercised

- Multi-service container orchestration with Docker Compose
- Log shipping and ECS-compatible field mapping with Filebeat
- Kafka as a decoupling layer, running in KRaft mode without Zookeeper
- Logstash filter development for parsing and timestamp normalization
- Elasticsearch index design and persistent volume management
- Kibana data views, saved searches, and dashboards
- Nagios host and service definitions for HTTP health checking
- Alerting design with Elasticsearch Watcher
