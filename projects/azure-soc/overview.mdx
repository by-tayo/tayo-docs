This lab builds a working SIEM in Microsoft Azure and points it at a honeypot. A Windows 10 virtual machine is deliberately left exposed — every port open, host firewall off — and its security events are forwarded into a Log Analytics workspace where Microsoft Sentinel can query them.

The result is not simulated data. Within hours of the VM going live, real authentication attempts from real hosts on the internet start landing in the logs, and those events can be mapped by source geography into a live attack map.

## Azure Resources

The lab is built from a single resource group containing everything it needs:

| Resource | Purpose |
| --- | --- |
| Resource group | Container for every service in the lab |
| Windows 10 VM | The honeypot — the thing being attacked |
| Virtual network | Network the VM sits on, with its associated security group |
| Log Analytics workspace | Where forwarded security events are stored and queried |
| Microsoft Sentinel | SIEM layer over the workspace — connectors, queries, and visualisation |

## Data Flow

```text
Internet attackers
      │
      ▼  (all ports open, host firewall off)
Windows 10 VM ──── Security Events ────▶ Data Collection Rule
                                              │
                                              ▼
                                    Log Analytics Workspace
                                              │
                                              ▼
                          Microsoft Sentinel — KQL · GeoIP · Attack Map
```

## Skills Exercised

- Azure resource deployment and resource group organisation
- Network security group rule configuration
- Microsoft Sentinel workspace setup and data connector installation
- Data collection rules and log forwarding to Log Analytics
- KQL query construction with filtering and time-range scoping
- Log enrichment with GeoIP data and geographic visualisation
- Interpreting real-world attack traffic patterns

<Warning>
  This lab intentionally exposes a virtual machine with no network or host firewall protection. Build it in an isolated subscription with no connectivity to anything you care about, treat the VM as compromised for its entire lifetime, and delete the resource group when you are finished — both to close the exposure and to stop the meter running.
</Warning>
